## Architectural correction and review

The browser stream used one awaited admission path for both current messages and
network-dependent history. A slow proof/profile/blob fetch therefore stalled the
remaining messages and heartbeat in the same stream chunk. The v0.8.15 durable
missing-key path was too narrow: known keys could still need network evidence.

The correction threads an explicit admission context through existing methods.
Foreground admission reads verified local evidence; a required network operation
defers the exact ciphertext through the existing durable queue. Background
admission uses the normal verification path. Both check current identity and pin
snapshots at the final transaction. Swallowed network errors cannot turn a
deferred record into an invalid notice or commit partially prepared work.
Legacy device-only V1 enrollment without a person remains supported. Current
roster removal, frozen persons, changed pins and missing conversation proof stay
enforced. A missing/changed pin on a secondary own device skips only that
forwarding copy; it cannot quarantine the valid incoming original. Existing
history catch-up retains the source and resumes after exact trust is restored.
No additional receive queue, worker pool, dependency, polling or wire format is
introduced.

Root and independent GPT-6.1-sol reviewers considered and rejected a duplicate
membership preflight, a timeout-only race leaving work in flight, and a mutable
engine-wide mode. The explicit context reuses the admission implementation and
keeps foreground and background operations independent. Review caught missing
current-recipient and concurrent key-change cases; focused regressions cover
them before source freeze.

Reference comparison used the primary implementations in
[TDLib UpdatesManager](https://github.com/tdlib/td/blob/master/td/telegram/UpdatesManager.cpp)
and [Signal Desktop MessageReceiver](https://github.com/signalapp/Signal-Desktop/blob/main/ts/textsecure/MessageReceiver.preload.ts).
The relevant principles are durable progress/gap recovery and staged durable
encrypted-message processing. This is a targeted comparison, not an audit of
those messengers or a replacement of AgentNet's E2EE with cloud plaintext.

## Acceptance and verification

- Display already stored chats independently of unrelated remote-workspace or
  old-history network waits. Measure first useful view, not only HTTP completion.
- A stalled old proof/file carrier cannot block a later fresh valid message or
  heartbeat. Preserve exact ciphertext durably before detaching its recovery;
  send receipts only after admission or an explicit held result.
- Keep recovery bounded and resumable, preserve current-key/signature/membership
  checks, and avoid uncontrolled parallel work or repeated full-history scans.
- Make request/answer/delivery UI consistent with exact authenticated evidence;
  keep unrelated replies, target-specific outcomes and uncertainty distinct.
- Add failing-before regressions, then focused signed/store/rendered checks.
  Batch the stable candidate before expensive required release qualification.
  Preserve valid unchanged evidence and report opt-in/platform skips accurately.
- Update the existing relay only after release gates. Clients update through
  their controls. Owner-phone catch-up and resource use require actual evidence.
