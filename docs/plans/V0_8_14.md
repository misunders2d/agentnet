## Compatibility and authority

`own3` explicitly adds inert direct-agent history, exact own-human remote
resolution, and durable original/revised proposal choices. Clients continue to
advertise `own2`; its earlier meaning is unchanged. A revised or sibling-device
proposal confirmation waits for an `own3` host. Original-device confirmation of
unchanged proposal bytes retains the existing legacy path. Only the exact
proposal receives the own-human exact-text exception; edited text uses ordinary
task grants or acceptance. Host-side transactional choice records prevent two
devices from independently running original and edited variants.

`tps1` separately advertises signed topic participation. The optional signed
topic field is absent for whole-chat access, empty for Main, or a stable topic
ID. An invitation with a new scope creates a fresh PID and execution session;
it does not narrow an existing broader invitation. Exact accepted message and
author evidence resolves inherited topic references; missing or ambiguous
parents wait instead of being treated as Main. Selected history, files, future
turns, captured controls and agent context enforce the same scope. The current
selected-agent/live-session reply receiver protocol cannot carry that scope,
so scoped sends using those receivers fail before committing any copies and
preserve the draft. Human replies and ordinary topic-agent requests remain
available. No receiver protocol or ambient-session reuse is introduced.

Capability advertisements fit18 names; parsing retains its prior32-name bound.
Neither capability is inferred from `rm1`. A queued encrypted copy rechecks its
captured key and relevant capabilities before delivery. These requirements add
no server-side plaintext or execution-policy layer.
