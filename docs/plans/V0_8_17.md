# v0.8.17 — outdated devices never impede others; phone receive and startup

Owner reports after v0.8.16 (October 10): the phone sat 20+ seconds on an empty
chat list, replies made minutes earlier never appeared, hundreds of held notices
offered no useful action, old requests stayed Pending/Waiting, and OKs asked to
"Decide on your Linux laptop" for work that had already been answered. Owner
decisions during the release: **the supported version is always the latest**
(outdated devices are suspended with an update notice; others must never
suffer), **every client updates itself** from now on (desktop, headless/server
daemons, browser), topic Done/Archive follow the person's own devices, and the
agent setup must be streamlined (one list of agents, one marked default —
planned for the next release in [AGENT_MODEL.md](AGENT_MODEL.md)). The web phone
app gets no further investment after this release; native apps follow.

## Root causes (evidence)

- **Empty chat list:** overview awaited notification support
  (`notifyView → features → /v1/version`, 30 s bound). Reproduced by the
  rendered startup regression, which fails on v0.8.16 and passes now.
- **Missing replies:** read-only relay query: the phone was not wedged; it
  drained about one message every 2–3 s (each history copy re-read all stored
  rows) and its 06:36 UTC answer sat behind 158 older own-device sync copies
  in a strict FIFO queue. Own-device sync carriers were also never
  acknowledged by receivers (MIXED-1), so they stayed queued forever.
- **Held notices:** Zenbook ran v0.8.14; bezos and linux-laptop behaved like
  v0.8.11–v0.8.13 and re-sent quarantined history copies on every presence
  change (866 copies of 4 records from bezos).
- **Pending / Waiting / "Decide on …":** linux-laptop (pre-v0.8.15 executor)
  answered with its physical copy id and never sent a final status; it has
  been offline since 18:37 UTC Oct 9.

## Scope delivered

Each item was implemented in an isolated branch with a regression that fails
before and passes after, reviewed independently for correctness and for
product rules/security, then integrated; a final cross-cutting review of the
whole diff found two release blockers (suspended agents could not finish
replies; session ends were not announced after member-list de-duplication),
both fixed before tagging.

- Relay: latest-only suspension with grace, allowlist for admitted work,
  recommendation follows the relay release, message acks renew stream
  liveness, heartbeats during long backlogs, unchanged member lists not
  re-sent, session start/end still announced.
- Clients: automatic update (fixed origin, SHA256SUMS, database test-run,
  switch only when idle, opt-out `agentnet update --auto off`), 426 means
  retry-after-update, old 426 failures re-queued after updating, suspended
  peers skipped and shown per device, per-device tolerance in browser group
  and guest sends, one requirement check for delivery and release.
- Receive: browser per-conversation IndexedDB index (O(conversation) work per
  message), unexpected admission errors set aside instead of ending the
  stream, early ping acknowledgement, foreground resume, no history echo; Go
  admission errors held instead of wedging, fair proof-retry cursor,
  authority-digest gating of member pushes.
- Sync hygiene: no device-history copy to the original's own recipient,
  byte-identical re-sent carriers folded into one held record, own-device
  carriers and deletions acknowledged once stored (MIXED-1).
- Truthful state: precise held codes and sender labels, records vs copies,
  Waiting only with fresh executor evidence, executor re-tells recorded
  terminal and queued states, OKs "Decide on" only for fresh decisions.
- Removed own device: invitations naming it no longer hold whole
  participations; edits of its messages resolve through the verified chain.
- Startup: cached notification view, read-view reuse in overview, lost
  first-load changes, bounded skin catalog and font sheet.
- Topic Done/Reopen/Archive sync (`tss1`), agent setup shows and edits the
  default agent and explains duplicates.
- **Mixed-version release gate** `TestMixedVersion` (real v0.8.16 binary vs
  this source) is now required before every release (AGENTS.md).

## Verification

- Full non-race suite on the merged candidate (all packages, incl. itest);
  mixed-version gate with v0.8.16 built from its tag; race UI partitions;
  CI on the release branch (native Linux/macOS/Windows, 13 race shards,
  desktop installers, container journey) — failures found there were either
  fixed (session-end announcement) or classified as pre-existing timing
  flakes by rerun, see the final run linked in HANDOFF.md.
- Synthetic measurements only (desktop Chromium, real IndexedDB): a reply
  behind 100 history copies with 5,000 stored rows went from 79 s to about
  8 s; ping acknowledgement from the whole backlog to under 0.1 s. **No
  physical-phone result is claimed.**

## Known limits and follow-ups

- Devices on v0.8.16 or older must be updated once by hand (Zenbook,
  bezos, linux-laptop, colleagues' computers); phones reload.
- A v0.8.16 task result with files from a device already suspended cannot
  upload through an old client after grace (new clients can).
- Deferred to the next release: audience pre-check relaxation for topic
  invites/moves with suspended members (branch prepared, not reviewed),
  agent model streamlining, native iOS/Android apps (separate Codex branch
  `feat/native-android`), per-sender relay fairness, minor review findings
  (HC-3..7, SEC-3, F3, F5, B2..B4).
