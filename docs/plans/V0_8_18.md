# v0.8.18 — interactive delivery during linked-device catch-up

## Final implementation contract — archive transport, October 10

The initial ordering and lane-only proposals below are insufficient as the
complete history design. Bootstrap/catch-up moves through bounded encrypted
archive chunks over the existing blob API. Live delivery never performs their
upload/download/import. Existing sender isolation is retained only as needed
for state sync and safely draining existing legacy queues. No new service,
poll loop, source election, or replacement crypto/admission framework.

Shared v1 format (Go, browser, native Android use the same protocol):

- Capability `ha1`; quiet rootless replica subtype `history-archive`, exactly
  one attachment, no executable request/target/notifications. Signed manifest
  body `{v:1,person:<id>,roster:<hash>,count:<1..50>,format:"agentnet-history-v1"}`.
  The envelope binds source and exact destination; current verified own-human
  roster checks remain required both when preparing/sending and importing.
- Attachment plaintext is UTF-8 JSON
  `{v:1,entries:[{envelope:<existing signed Envelope>,blobs:[{id:<id>,ct:<base64>}]}]}`,
  at most 4 MiB plaintext and 50 entries. Use the existing age attachment
  encryption/hashes; no new compression dependency or unbounded decoder.
  Child envelopes are inert history/device-history or necessary root/group
  proof/context records only. No ordinary message/question/task children.
- Structural blob ciphertext is embedded only where required by a child's
  signed blob manifest. Verify exact ID, size and digest and durably cache it
  before ordinary child admission. Ordinary historical attachments remain
  lazy; this is not a copy of every file. Every child still passes existing
  envelope signature/decryption/shape and admission checks. No fabricated
  per-child relay receipt; imports cannot execute work.
- Every own human device contributes the data it actually holds; preserve
  existing logical IDs/author keys, hashes and source snapshots/tail cursors.
  Durable archive mapping and source cursor advancement must commit together.
  Existing local ciphertext rows may be staging only, never new individual
  bootstrap POSTs. Recognize staging explicitly; never label it delivered.
- Source progress may commit with exact sealed children and copy mappings in
  a durable, non-sendable `archive_staged` state. This preserves recoverable
  source data without holding the single SQLite connection while a chunk is
  encrypted and fsynced. A background worker persists the encrypted chunk,
  then atomically maps its staged records. Restart must discover unbundled
  staging; no cursor may advance without either durable staging or a chunk.
  Upload outside
  the live sender and only enqueue its small descriptor once uploads are
  already complete. Bound outstanding chunks per exact source/recipient key;
  do not prebuild the whole history. An oversized record stays incomplete
  with a concrete error; never skip its cursor silently.
- Receive dispatch only records the descriptor/job. Acknowledge it after
  downloaded ciphertext passes its signed hash and is durably retained,
  not merely after saving a URL/job (manual cleanup has no fixed 30-day floor).
  Import in bounded background steps, persisting progress. Crash replay uses
  existing original-ID/logical-ID deduplication. Missing proofs remain durable
  under existing recovery; revoked/current authority still fails closed.
- Capability negotiation retains legacy receivers during migration. Preserve
  already queued/custody history and do not reset/relink/purge. Browser source
  and receiver parity are required; a phone may hold unique history.
- Bootstrap snapshots use archives; post-snapshot tail records keep ordinary
  signed inert copies with an explicit local live-routing marker. A full cold
  history window must not stop bounded fresh-tail production. Routing markers
  do not grant authority or turn historical requests into executable work.
- Upgrading sources reannounce existing inert custody envelopes with the exact
  original IDs and bytes. A signed identical retry may demote that sender's
  still-custody copy from legacy live routing to sync; it cannot promote sync,
  change content/attachments/receipts, or modify acknowledged copies. Already
  written stream bytes cannot be recalled; disconnected sources must update
  before their old copies can be classified.

Review basis: Meta's July 2021 multi-device description uses encrypted recent
history bundles (https://engineering.fb.com/2021/07/14/security/whatsapp-multi-device/).
