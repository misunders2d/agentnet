## Current design

- Signed originals, IDs, authors, timestamps, files, audiences, reply ancestry,
  task/approval/execution records and native sessions remain intact. Personal
  placement facts change display grouping only. Unknown or erased originals do
  not become messages; copied tasks remain inert.
- Organization is bound to the original execution destination: host address,
  original host fingerprint and concrete agent ID. Legacy empty IDs remain
  distinct. A1 resolves that identity from authenticated originals and immutable
  ancestry before T1 projection. Preview, apply, undo and projection reject
  mixing agents or host keys. Display placement never chooses a future executor.
- A new topic's identity is the review operation ID. Its placement has one
  `synthetic` flag; its private title uses the existing title register keyed by
  that topic ID. Navigation derives an earliest held original without replacing
  the topic ID or changing ancestry. Existing destinations retain their anchor
  and metadata; partially moved roots leave a navigable unselected remainder.
- Existing preview/apply/undo routes accept `peer` in place of `conv`. Reviews
  bind exact retained originals, destination identity, source synthetic-topic
  flags and current placement inputs. Stale review is refused. The same exact
  operation retry is inert, including after undo and restart. Originating-device
  undo restores selected sources atomically and refuses later placement.
- Current own-human roster/key admission and durable encrypted carriers are
  reused. Independent `dts1` isolates older readers without blocking supported
  devices. Placement revision/writer/destination ordering converges across
  linked devices, duplicate and reordered delivery, and independent offline
  choices. Names synchronize through the existing private-title mechanism.
- `agentnet topic` provides JSON list/show/preview/apply/move/merge/undo, with
  `--to TOPIC` or `--new "Topic name"`. Comic reuses selection and topic-menu
  controls, a filtered existing/new destination chooser, exact review, recovery
  and undo. API contracts are in [HOST_API_ROUTES.md](../HOST_API_ROUTES.md) and
  [UI_SKINS.md](../UI_SKINS.md).
- `dts1` consumes one reserved advertisement slot: producers advertise at most
  31 names; existing readers still parse 32. No shipped capability is redefined.
  Placement tables are part of a new, unshipped schema step; shipped migrations
  remain unchanged.

## Preserved qualification findings

Before integration, the original existing-topic draft passed focused
protocol/envelope and CLI baseline checks at source digest
`828e7c20bc0a2109aed5235d29a035ec4a3e29808ab6f720e2236637c0ae2969`
(1,755 source files). That baseline is distinct from the current new-topic and
exact-identity evidence. The first CLI attempt was denied its disposable

required test permission.

Current focused testing caught two synthetic-navigation omissions: normal local
outbox index rows have an empty author field, and read-scope classification first
looked up a message row for a non-message topic ID. Both were corrected using
held-original resolution; no signed message or execution row was rewritten.
A client build also observed a transient concurrent A1 source compile error;
it was corrected in A1 ownership before the current client checks.

The earlier draft's Chromium temporary-path socket limit and capability sorting/
producer-ceiling failures remain historical draft findings. No timeout was
raised or test removed to obtain the current results. Direct source authoring
without build staging cannot type-check copied shared modules; the successful
check used the existing build's staging layout.
