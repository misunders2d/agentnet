# AgentNet revival — M1: enrollment and end-to-end encrypted messaging

Status: M1 candidate on branch `revival/mvp`. Not reviewed, released, or
deployed. The legacy Python implementation in this repository is untouched and
unrelated to this Go code.

## What works

- One `agentnet` binary is both the client CLI and the Hub (`agentnet hub serve`).
- The Hub creates a self-signed TLS certificate and a one-time bootstrap admin
  invite (`<data>/bootstrap-invite.txt`, owner-only, path logged, content never
  logged). Invite codes carry the Hub URL, person label, secret, and the Hub
  certificate, so clients verify the Hub without skipping TLS checks.
- `join` generates per-agent keys locally (Ed25519 signing, age X25519
  encryption), saves them, proves possession to the Hub, and enrolls as
  `person/agent`. If the Hub's answer is lost, running the same `join` again
  finishes enrollment with the same keys; the used invite refuses other keys.
- Hub URLs are bare `https://host[:port]` origins; a trailing `/` is accepted.
- Every Hub request is signed over method, path, body digest, time and nonce;
  replays, stale times, and substituted bodies/paths are rejected.
- `send`/`reply` encrypt to the recipient and sign the envelope. The Hub stores
  ciphertext only and pushes it over one long-lived stream (`daemon`), with a
  ping every 90 s and jittered reconnect backoff. There is no inbox polling.
- Receipts say only what is known: `custody` = the Hub stored it;
  `delivered` = the recipient verified, decrypted and stored it;
  `quarantined` = the recipient received it but could not verify it
  (tampered, malformed, or signed by a changed sender key). A quarantined
  message becomes `delivered` if the recipient later trusts the new key.
  Messages without a receipt are pushed again on reconnect, and receipts the
  Hub did not record are re-sent; both sides deduplicate by message id.
- A message the daemon cannot process yet (Hub or directory briefly
  unreachable) ends the connection; it reconnects with backoff and the Hub
  pushes the message again. Ordinary requests time out after 30 s.
- If the Hub is down, messages to previously trusted peers queue locally and
  the daemon retries them after reconnecting (and on each ping).
- Recipients verify the sender signature against their trusted key and check
  that the encrypted id/from/to match the signed envelope. Tampered, misrouted
  or malformed messages are quarantined, never shown.
- The first key seen for a peer is trusted. A different key from the directory
  blocks sending and holds incoming messages until `agentnet trust ADDRESS`.
- Admins revoke agents; the Hub rejects their requests, closes their stream,
  and refuses messages to them.

## Try it

```sh
go build -o agentnet ./cmd/agentnet
./agentnet hub serve --data ./hub --listen 127.0.0.1:8443 &
./agentnet --home ./alice join --agent laptop "$(cat ./hub/bootstrap-invite.txt)"
./agentnet --home ./bob join --agent desk "$(./agentnet --home ./alice admin invite bob)"
./agentnet --home ./bob daemon &
./agentnet --home ./alice send bob/desk "hello"
./agentnet --home ./bob inbox
```

Tests: `go test -timeout 120s ./...` (includes a real TLS Hub with two
clients: push delivery, offline catch-up, Hub restart, duplicates, Hub-side
tampering, key substitution, and revocation).

## Security model and limits

- **The Hub directory is trusted for first contact.** A malicious Hub could
  hand out its own key before you first talk to someone. Compare fingerprints
  (`agentnet whoami` / `agentnet fingerprint ADDRESS`) out of band to rule
  this out. Later key changes are caught and block sending.
- **Metadata is visible to the Hub:** who talks to whom, when, and sizes.
- **No forward secrecy.** A stolen agent key decrypts that agent's past
  messages captured from the Hub or local storage. Lost keys cannot be
  recovered; undelivered messages to them become unreadable.
- **Revocation is not retroactive** and does not remove already delivered data.
- **Local storage is plaintext** inside an owner-only directory (POSIX 0700/0600;
  on Windows a protected owner-only ACL). Anyone with the user's OS account can
  read it.
- An invite label is an admin's assertion about a person, not a verified email.
- A Hub-hosted agent is an ordinary enrolled agent and decrypts only messages
  addressed to it.
- Key files and databases must be owner-only; a restored database with wider
  permissions is refused rather than silently used.

## Not in M1

Files, questions vs tasks, sessions, direct peer connections, A2A, harness
integration, container image, public-CA/reverse-proxy TLS mode, key rotation,
retention limits. Windows and macOS builds cross-compile; they have not been
run on those systems.
